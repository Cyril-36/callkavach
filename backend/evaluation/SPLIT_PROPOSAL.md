# Proposed family-aware evaluation split

**Status: proposal for Cyril-36 to approve.** No held-out set is frozen, and no
transcripts, paraphrases, translations, or recordings are generated by this
proposal.

## Grouping unit and current assignment

Split by an independently authored **scam/genuine pair group**, never by an
individual call. The two labels in each current scenario seed share an origin
and must receive the same assignment. The six pairs in `data/families.json` are
the only reviewed seeds currently available, one pair per scenario type. I
propose using all six as **development seeds** and reserving new, independent
pairs for the held-out test.

This is a proposed allocation of existing seeds, not a claim that a held-out
test already exists. With only one pair per scenario, assigning any current
pair to held-out would leave that scenario without an independent dev pair.
The resulting score would mix unfamiliar scenario types with model performance
and would not cover all six types in both partitions.

## Independent families needed

At least **one newly authored and reviewed scam/genuine pair per scenario** is
needed for basic held-out coverage of all six types: six additional pair groups
or 12 new family records. Those pairs must use a distinct situation and evidence
progression, not merely different wording of a current seed. This minimum is
still a small test: a planned 300-call set made from only six held-out pairs
would repeat each family about 25 times on average, so its apparent 300 cases
would contain much less independent scenario diversity.

For a stronger 300-call claim, propose **three independent held-out pairs per
scenario** (18 pair groups, 36 family records), subject to owner review and the
available time. This is a planning target, not a statistical guarantee. If the
team cannot author and review enough independent pairs, use a smaller labelled
benchmark and report the actual number of families and calls rather than claim
the planned 300 held-out calls. Keep dev calls separate from the 300 held-out
target; do not count a dev split within 300 as 300 tests.

An independent pair should change more than names or surface wording: vary the
underlying situation, evidence order, pressure tactic, dangerous-request mode,
and benign reason as appropriate while retaining the scenario label. The owner
must decide whether a proposed new pair is genuinely independent. A simple
similarity score or this repository's structural validator cannot decide that.

## Leakage prevention before generation

1. Have the owner review and freeze a manifest mapping every pair group to
   `dev` or `held_out` **before** generating paraphrases or translations.
   Preserve each call's `family_id`, pair-group ID, source script/prompt ID,
   language, and recording/script lineage in the later evaluation manifest.
2. Put both labels of a pair and every derivative of either family in the same
   split: paraphrases, translations, code-mixed versions, audio renditions, and
   repeated-speaker recordings. A new voice or language does not make a new
   independent family.
3. Review new candidate pairs against existing seeds and each other. If two
   share the same underlying story, script template, or distinctive evidence
   sequence, group them together or keep one out of the held-out set. Check
   lineage as well as wording; text similarity alone misses translated copies.
4. Keep held-out scripts and their generated calls out of dev exemplars,
   verifier prompts, embedding examples, baseline phrase selection, and rule
   tuning. Freeze the detector configuration and phrase list before the first
   held-out run. Do not inspect held-out outcomes to adjust thresholds.
5. Audit the final manifest for any pair group or source lineage appearing in
   both splits. If leakage is found, remove the affected group from held-out
   reporting or disclose and rerun under a newly frozen split; do not silently
   relabel individual calls.

Report both call counts and **independent pair-group counts** by label,
scenario, and language. State whether audio speakers overlap across splits.
Synthetic results are coverage of these authored situations, not real-world
scam prevalence or proof of generalization.

## Owner decision requested

Please approve or revise (1) assigning the six existing pairs to dev, (2) the
minimum and target number of independently reviewed held-out pairs, and (3) the
pair-group and lineage rules. After approval, the owner can freeze the manifest
and authorize dataset creation. No 300-call dataset should be generated from
this proposal alone.
